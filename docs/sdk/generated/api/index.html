RTFW 1.2.1 public SDK source reference

Manual · Recipes

Selected entry points link to exact checked declarations. All default and named optional headers are reproduced with comments and line anchors. This is not a semantic C++ index; private/detail declarations remain unsupported internals.

Lifecycle, ownership and integration

  • rt::Runtime — Configure and finalize before start; keep borrowed owners alive until checked stop succeeds.
  • Runtime::configure — Control-plane configuration; validate capacities and policy before finalization.
  • Runtime::finalize — Compile and reserve resources; inspect failure before admitting frames.
  • Runtime::start — Startup must complete before frame admission; borrowed owners already exist.
  • Runtime::step — Explicit frame context, bounded callbacks and checked status; failure may leave application effects.
  • Runtime::stop — Retain unresolved borrowed resources on failure and retry; destruction is not recovery.
  • HostExecutorAdapter — Copied accepted jobs execute exactly once; opaque completion/scratch identities remain borrowed.
  • RuntimeClock — A monotonic clock remains host-owned and outlives Runtime.
  • RateExecutionPolicy — Explicit finite release/dispatch capacities; logical rates are not physical deadlines.
  • LiveControlPolicy — Fixed mailbox/producer/record/payload budgets; application apply and side-effect recovery remain external.
  • SampledIoChannelRegistration — Declared encoding, clock, freshness and safety policy; accepted submission is not an acknowledged safe state.
  • Runtime::checkpoint_size — Size caller-owned storage before writing; registered state is not an arbitrary process snapshot.
  • Runtime::replay_active — Use a compatible trusted artifact and deterministic mock/loopback providers.
  • Runtime::replay_live_control — Payload-bearing artifacts are explicitly trusted; v2 is opt-in for admission history.
  • RuntimeConfig — All capacities are explicit; portable defaults do not establish RT qualification.
  • MemoryProvider — Provider tokens and arenas remain live through failed rollback/stop; report truthful observations.
  • HalV2BackendApi — Capability and lifecycle contract; optional extensions do not imply physical support.
  • Status — Check every lifecycle and frame result; status_message supplies stable human-readable categories.
  • ConfigBuilder — Optional helpers delegate to raw validation; no implicit capacity or hidden Runtime lifetime.
  • GraphBuilder — Typed registration remains bounded and explicit.
  • CheckedStopGuard — Explicit checked stop/retry is required; unresolved destructor cleanup terminates.
