## Independent system-risk review and repairs

The uncommitted batch received an independent full-diff system-risk review on
2026-08-12. Two material findings were reproduced and repaired inside the
approved M18-01 paths:

1. **High — self-contradictory trends could produce a passing proposal.** The
   validator trusted `stable: true` without checking the numeric endpoints and
   checked only the thermal maximum range. A record with resource growth, a
   maximum below its endpoints, or out-of-range thermal start/end values could
   pass and feed a support-matrix-eligible proposal. Validation now requires
   every maximum to cover start/end, stable resource end not to exceed start,
   and all thermal values to remain in `[-100, 300]`.
2. **Medium — artifact validation could exceed its declared resource bounds.**
   File count was rejected only after `os.walk()` had enumerated the complete
   tree, directory entries had no aggregate ceiling, and actual aggregate bytes
   were rejected only after all individually bounded files were hashed. The
   validator now streams at most 2,304 tree entries, stops after the 257th file
   entry, checks open-file size against the remaining 512 MiB budget before
   reading, and stops hashing on the first actual size violation.

New behavioral tests reproduce the trend contradictions, bounded tree scan,
and aggregate-byte early stop. The permanent documentation and release
contract checks now retain the tree-entry ceiling token. No runtime, ABI,
package, support matrix, workflow, hardware evidence, or claim boundary was
changed by these repairs.

## Rollback and residual risk

Rollback is one coherent revert of the four schemas, tool, fixtures/tests,
documentation/checker/digest integration, governance synchronization, and this
evidence file. There is no runtime state, data migration, support entry,
hardware mutation, release, or deployment to reverse. If an external
version-1 record exists, retain a reader or archive it explicitly as
non-promotable; never rewrite its raw artifacts.

Residual risks:

- SHA-256 detects byte substitution only relative to the reviewed digest; it is
  not authentication, signing, or trusted provenance.
- A reviewer string and UTC timestamp are untrusted. Human inspection of
  externally retained pre-run plan provenance remains mandatory.
- Schema/tool completeness cannot prove that tuple statements, raw artifacts,
  or reviewer assertions are operationally true.
- The fixed bounds and strict version-1 field/applicability model require human
  schema and security review before merge and versioning review before change.
- M17-05 still prevents a real combined campaign/proposal from relying on the
  intended native composition path.
