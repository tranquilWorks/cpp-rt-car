## Independent system-risk review repairs

The uncommitted batch received an independent system-risk review against the
active batch, public/package compatibility boundary, affected lifecycle and
safety contracts, tests, and claim language. The review made these bounded
repairs before final verification:

- kept the reserved `memory.host-provider` row zero/not-applicable and rejected
  declarations for it, preventing selected provider storage from being counted
  a second time in excluded and closed totals;
- rejected per-role and aggregate declarations that contradict already-known
  caller or host-adapter cardinality;
- retained a persistent marker for available runtime-stack results so a
  checked cleanup retry after failed startup republishes success and clears the
  prior cleanup error before entering `stopped`;
- treated unavailable native stack metadata as `unknown` in best effort rather
  than failing startup or publishing a zero-byte logical total as exact.

Behavioral regressions cover provider no-double-counting and declaration
rejection, unavailable best-effort stack facts, and failed-start owning-lane
cleanup retry with public-report recovery.

## Deterministic CI repair

Mandatory CI run `30966886465` reached the Windows Debug warnings-as-errors
build and failed before tests. The first causal diagnostic in the retained
failure log was MSVC C4324 at `tests/test_device_runtime.cpp:64`, promoted to
C2220 by `/WX`: appending a `MemoryRegionId` to the test fixture's 64-byte-
aligned 128 KiB storage slot forced tail padding. The final process exit was a
cascade from that compile failure.

The bounded repair keeps the provider allocation slot at its original exact
aligned size and moves the rollback/release region metadata into a separate
stable provider token. No warning was suppressed, no test was weakened, and no
runtime, public header, C ABI, device ABI, package, schema, provider boundary,
or qualification claim changed. The repair changed only
`tests/test_device_runtime.cpp` and this retained evidence file.

The available Linux host has no MSVC or Windows cross-toolchain, so the exact
Windows Server 2022 v143 `/W4 /WX` command was not rerun locally. Its affected
warnings-as-errors target rebuilt with the available compiler, the three
fixture-dependent rollback tests passed, and the complete repository-local
verification passed. A mandatory CI rerun remains required before merge.

Mandatory CI rerun `30967606263` passed every build and test surface except
the Windows runtime-policy tests. Windows RelWithDebInfo returned
`Status::invalid_config` from three assertions that expected Linux-only strict
native stack observation: closed accounting cannot become exact when live
runtime stacks are unobservable, and strict stack residency cannot reach the
injected startup/cleanup transaction when that native capability is rejected
during finalization. Windows Debug was then cancelled by fail-fast.

The repair makes the platform contract explicit without changing production
behavior. Linux still must close live stack accounting and exercise injected
strict-residency mismatch, rollback, recovery, and owning-lane cleanup retry.
Non-Linux must retain an incomplete/unknown live stack report, reject strict
closure or residency with `invalid_config`, preserve the correct lifecycle
state, execute no native startup operation, and remain stoppable. No native
capability is inferred and no unsupported Windows qualification is added.

Mandatory CI run `30971707284` confirmed that both non-Linux strict-residency
tests pass, then exposed one aggregate-exactness assertion in the accounting
test: an `unknown` runtime-stack row combined with declared external facts is
truthfully `partial`, not `unknown`. The follow-up repair changes only that
aggregate expectation; runtime behavior and row-level exactness are unchanged.

resident bytes are a one-host live `mincore` sample, not a durability, latency,
RT, or physical-memory qualification claim.

The fully declared host-adapter test supplied declared-only caller-frame and
two-worker stack totals of 8 MiB and 16 MiB. It produced a 3-region, 24 MiB
external-stack row, an exact zero-cardinality runtime-stack row, a

remain trusted caller metadata, not native observation.

Control-row commitment/residency fields remain zero because the exact logical
extent ledger does not infer allocator page commitment or physical residency.

backend-declared bytes against constructed storage and device ABI v1.

## Changed and preserved invariants

Changed:

- The additive C++ policy/report API now exposes bounded accounting
  declarations, stable keys, exactness, aggregate totals, and completeness.
- Finalization validates actual fragmented control extents against the frozen
  `MemoryPlan` terms.
- Runtime-owned stacks are observed live and cleaned on their owning lanes.
- Stop/startup rollback coordinates device, lane, stack, and selected-region
  ownership with explicit pending state and checked retry.

Preserved:

- Stable C ABI v8, 70-export allowlist/fingerprint, SONAME 8, and device ABI v1.
- Runtime schema 7 and all 25 keys; observability and artifact schemas.
- Six-row `MemoryPlan::planned_bytes` equation and the provider's three-region
  acquisition boundary.
- No ordinary heap allocation on declared RT lanes after successful start; no
  hidden thread creation, file I/O, blocking mutex, unbounded wait, or spill.
- Multiple runtime isolation, deterministic behavior, package targets/headers
  and 1.x aliases, version 1.2.1, support/qualification matrices, and
  Apache-2.0.

## Rollback

Revert the M15-04 public closure metadata/declarations, exact control ledger,
stack lifecycle transaction, cross-category coordination, tests/CI,
documentation, evidence, and digest ledger as one coherent batch. Before
discarding a live integration, use checked `stop()` until all device, backend,
lane, stack, memory-policy, and provider-token ownership is resolved. Never
detach, cancel, force-unmap, clear, or relabel unresolved ownership. There is
no data migration, persistent host setting, support promotion, release, or
deployment action to reverse.

## Residual risks and unperformed validation

- Declarations can be syntactically complete while operationally false; they
  remain trusted metadata.
- The logical control ledger proves bounded exact non-overlap against the
  constructed C++ storage model, not allocator page commitment or physical
  residency. Future container/capacity changes must keep estimator and actual
  extent inventory synchronized.
- Linux stack residency is a transient one-host `mincore` sample. Stack layout,
  guard behavior, libc behavior, `RLIMIT_MEMLOCK`, and capabilities vary by
  target host. `mlock` has no independent lock readback here.
- Mandatory GitHub CI runs `30966886465`, `30967606263`, and `30971707284`
  exposed the repaired Windows MSVC padding and platform-expectation failures.
  The local focused gates pass, but a passing rerun of the required GCC
  11/Clang 14 ASan/UBSan matrix, MSVC v143 matrix, GCC 11 TSan fresh-process
  job, determinism exchange, relocated archive matrix, and hosted package gates
  remains pending.
- Required human accounting, public-API, lifetime/concurrency, native-call,
  rollback, compatibility, and ABI review was not performed.
- No privileged native validation, controlled timing, physical CUDA,
  FPGA/XDMA, combined accelerator, direct peer DMA, HIL, Unreal, field,
  latency, worst-case execution, thermal, endurance, RT1, RT2, signing,
  release, staging, deployment, or production validation was performed.
