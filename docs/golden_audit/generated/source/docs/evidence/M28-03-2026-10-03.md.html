## Historical evidence and classification

- M27-02 local and hosted mock/native unselected tests: startup -2 instead of -18,
  native event argument 8000000ns, then cleanup0/live0. Initialized hosted TSan
  reported the same functional assertion. M27-07 Clang Debug native and M28-02 GCC
  Debug mock logs repeat it. Their raw logs are retained with source/hash bindings.
- M27-02 Windows Debug: SampledSimulationStartup returned -18 instead of0 after
  2024ms, event argument8000000ns, entered1, cleanup0/live0. This is a distinct
  observation. Its exact scheduling/driver cause is unproven.
- M27-02's unchanged native held-work baseline records start/channel -2/-18,
  two pending stops -2, live1, then actual completion, cleanup0/live0. Current
  independent controls confirm that this ownership precedence is required.
- An unchanged fixture Card holds its wait_user_event callback for at most two
  seconds independently of the Runtime logical clock and simulator host watchdog.
  Explicitly retaining that hold reproduces a two-second timeout on this host.
  It is an existence/control result, not proof of the old Windows cause.

## Acceptance and actual entry point

The new tests/closeout_startup executable directly configures/finalizes/starts/
steps/stops the public Runtime and actual XDMA backend using an injected driver.
It includes the original public fixture verbatim and wraps only new test callbacks.
It never accesses a device node. The 8ms safe argument and original two-second
fixture wait remain exact; an explicitly selected100ms simulation watchdog drives
new held-work controls, as in existing startup reliability coverage. Logical expiry
is checked separately on returned completion. No original timeout is altered.

Thirteen fixed scenarios cover successful safe startup/frame/shutdown, terminal
native timeout, late successful native readback after logical expiry, one-shot
shutdown error, timeout before backend acceptance, selected/unselected mock and
unselected native pending work, a successful owner while another retains work,
the original two-second driver bound, and concurrent independent owners. Exact
channel status/safety, no invalid application/timeline publication, restart/step
refusal while pending, live borrowed ownership, repeated stop, one final native
shutdown, zero Runtime outstanding work and zero frame/checked-stop allocation
are asserted. An explicit allocation positive control validates the observer.

The baseline and current Runtime production are identical. All normal controls
pass; there is no causal baseline defect/corrected production claim. Existing
13 CommandBatch.SampledSimulation tests and startup_poll_reliability pass unchanged.
Historical failures remain unresolved observations, never erased by those passes.
