## Delivered behavior

The optional installed source kit captures copied global schema2 snapshots in a
1–64-slot host queue, at most256 events and32 metrics per slot. Candidate cursors
commit only after admission; full, disabled and failed capture preserve them.
Sinks acknowledge entire snapshots; failure retains the front, and a partial
external write may duplicate records. Close retains pending data for drain or
explicitly counts discarded batches/events. Runtime inspection remains a
caller-owned quiescent host operation, serialized with Runtime control/execution.

Official optional protobuf modules produce native Perfetto TrackEvent files and
OTLP/HTTP logs/metrics; Windows uses native TraceLogging. The intermediate NDJSON
spool is explicitly a separate kit format. Exact session/Runtime/config identity,
caller-supplied clock anchors, original timestamps, interval metric semantics,
Runtime loss and exporter backpressure are retained. Strict spool validation
reconciles sequence spans, record counts and reported losses across batches.

Runtime, all native/experimental/benchmark implementations, original tests,
public ABI/schema/defaults and SDK header/target inventories remain unchanged.
The kit is installed as data/source and compiled only by selected consumers.
CAP-M20/scenario/3 is mapped to its implementation and native tests; every other
M20 engineering/manual release requirement retains its prior disposition.

## Retained findings and corrections

Initial native SQL used dotted annotation names; Trace Processor normalizes them
to underscores. Initial collector configuration omitted the required disabled
metrics level. Those failed native attempts are retained. The first package
harness expected different wording for a correctly rejected absent kit; the
assertion was corrected and independently rerun, then a fresh complete package
run passed. No original test or product assertion was relaxed.

Initialized TSan proved the new synthetic clock's plain increment raced Runtime
workers. All new sample/test clocks now use atomic fetch_add; fresh initialized
runs pass. A separate GDB trace captures intermittent TSan allocator mmap crashes
before main. Only those documented startup failures/mapping errors are retried;
actual sanitizer warnings stop the gate. Earlier missing-include compiler
attempts, an incorrectly applied diagnostic file-size limit, and a PIE ASan
fatal-signal loop remain recorded. The latter raw log is losslessly compressed
with a verified SHA256 after terminating the owned runaway diagnostic process.
Non-PIE builds retain full sanitizer instrumentation and no suppressions.

Windows candidate01 failed to compile a string_view passed to TraceLoggingString;
a terminated local copy now lives through the emission call. Candidate02's
installed native ETW consumer compiled and actually collected/decoded records.
The final loss-validation repair closes a separately reproduced gap where an
interior event could disappear without increasing reported loss. All earlier
failed attempts remain separate from subsequent successful evidence.

## Limits and risk disposition

The clock mapping is offset-only and caller-certified, with caller-supplied
uncertainty; no clock synchronization/drift or RT timing guarantee is inferred.
Fresh trace cursors cannot recover prehistory. Cross-file continuity/deduplication
belongs to the caller. Receiver acceptance and ETW emission attempts do not prove
downstream or exactly-once delivery; ETW enablement may change during a batch.
Native Python encoders reject signed-int64 metric/timestamp overflow. Spool and
ETW keep uint64 values; Perfetto charts may use floating point, with exact decimal
metric annotations retained. Separate rate/live-control/sampled-I/O formats are
not silently exported as global schema2. See `M27-04-risk-review.md`.

No hardware/HIL/RT/human/Unreal/controlled-performance/production-signing/release/
deployment evidence is asserted. Historical M23 precise-cause and experimental
clock-initialization limitations remain independent. The old Windows sampled-
simulation timing failure is retained without changing its2s/8ms bounds. There
is no target/local gate waiver; integration requires actual exact-head success.
