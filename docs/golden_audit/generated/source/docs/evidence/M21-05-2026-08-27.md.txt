## Implemented closure

- `MixedRateClosurePolicy` is copied while configuring and freezes semantic
  policy identity, fixed action capacity, bounded replay record/byte limits,
  the closed overwrite policy, and deterministic-backend replay requirement.
- `MixedRateActionRecord` is a fixed 256-byte schema-1 C++ record. A
  finalization-time ring reserves monotonic sequences, reports busy drops and
  committed overwrites, binds cursors to one Runtime, reports exact gaps, and
  makes lossy transcript ranges replay-ineligible.
- Runtime actions correlate rate decisions, settled device outcomes, sampled
  publication/selection, safe-state acknowledgement, watchdog/degradation,
  and checked stop. Records contain content identities rather than sampled
  payload bytes, raw addresses, callbacks, vendor handles, or thread identity.
- A closure-enabled checkpoint conditionally appends one ordinary
  `rtfw.mixed-rate` schema-1 state record at a quiescent boundary. Existing
  checkpoint/input-log schema constants and the disabled legacy byte path are
  unchanged.
- Active-replay schema 1 is a separately bounded fixed-width little-endian
  artifact with a 384-byte header, direct-index input descriptors, fixed
  actions, per-record checksums, and a whole-artifact checksum. Inspection and
  replay prevalidate encoded bounds, identity, ordering, checksums, and
  reserved fields before restore.
- Active replay permits only frozen deterministic-mock backends, consumes
  recorded logical decisions rather than live watchdog/completion timing,
  re-executes provider/loopback work, and compares generated actions,
  terminal status, sampled metadata, content identity, and final state.
- `SampledIoLoopbackBackend` retains its HAL-v2 tables and gains only a bounded
  instance-local logical-action inspection/reset surface; it owns no thread or
  global mutable state.
- A table-driven fixture built from public installed headers runs CPU plant,
  loopback device sensor, CPU controller, loopback device actuator, and CPU
  observer work across 100 ms, 150 ms, 225 ms, and 450 ms periods. Repository
  tests and the package consumer share the same fixture.
- Existing six-row `MemoryPlan` accounting exposes exact mixed-action and
  replay-control subtotals. Caller artifacts, registered device buffers,
  output spans, and backend-private loopback storage are excluded.
