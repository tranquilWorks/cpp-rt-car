## Reconstructed implementation and acceptance mapping

- An additive 48-byte C++ retention policy explicitly selects trusted format v2.
  Finalization freezes identity, bounded descriptors/payloads and validation
  scratch, all included in MemoryPlan. Existing structure layouts and v1
  constants remain intact.
- A bounded admission journal retains original accepted payloads, slot and
  producer ownership, action ordering, rejected-counter attribution, future
  records and admission closure. Exhaustion or lost action history makes export
  explicitly ineligible. Default action telemetry remains payload-free.
- The separate 448-byte v2 header and 184-byte admission descriptors have checked
  bounds, reserved fields, checksums and ordered topology validation. The complete
  history is validated while producers are quiescent, before checkpoint restore.
  Replay reconstructs private state and normal settlement, comparing complete
  Runtime state and action identities. Incomplete v1 histories fail explicitly.
- Terminal slots remain owned until their original-record action is reserved or
  emitted, preventing producer reclamation from overwriting action metadata.
- Focused cases cover replacement/rejection composition across two/eight frames,
  host/rate targets, multiple mailboxes, future and pre-checkpoint admissions,
  slot reuse, rollback, invalid/full/stale/busy/missed/stopped/exhausted outcomes,
  repeated/concurrent runtimes and producers, malformed-input nonmutation,
  explicit retention exhaustion, and both supported clear-fault payload forms.
- Public package consumers select v2 only for --replaced/--rejected and measure
  allocation during admission/step and replay. Default consumer remains v1.
