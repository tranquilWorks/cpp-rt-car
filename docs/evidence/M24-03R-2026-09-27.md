## Cause and bounded repair

Runtime requests command stop, joins execution, then unregisters memory before
backend shutdown. CUDA previously rejected unregister for every pending or
quarantined reference. Runtime skips backend shutdown while registered buffers
remain and stops its poll lane; retry cannot break the ownership cycle.

Only CUDA's private unregister implementation changes. It claims each nonfree
slot before inspecting references; an already-owned slot rejects cleanup for
retry. Referenced pending/quarantined work remains rejected while running.
After explicit command stop, checked host cleanup may synchronize its event or
stream, combine context-pop status, and retire the slot exactly once before
unregister. Failed push/sync/pop restores original slot state and retains every
registration/outstanding reference. No running executor or normal poll path gains
synchronization, allocation, new threads or waits. Unsupported cancellation and
permanent-lost reset rejection remain unchanged.
