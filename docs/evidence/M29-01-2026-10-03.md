## Cause, repair and acceptance mapping

The old loopback uses `kOwned` both for unpublished submit storage and poll's
exclusive read. Cancel reads/writes that storage without claiming it and may
publish it to polling. An injected timeout never release-publishes its completion.
New test-owned copies preserve the real callback body and add two scheduling
seams: submit paused after slot claim before completion construction, and poll
paused after claim before copying. Both baseline cases abort at the unchanged
new oracle: cancellation must not claim exclusively owned storage. The first
also detects stale prior-ID publication during reuse. The controls order accesses
and do not rely on provoking undefined data races. No production hook is added.

The retained initialized TSan M28-02 attempt46 independently identifies old
cancel/submit non-atomic completion access. `baseline-binding.json` verifies the
entire old loopback implementation is byte-identical to this batch's baseline.
The original report is retained, not replaced by a clean rerun.

The repair adds private published-held timeout state. Submit release-publishes
all completed writes/accounting; poll claims ready storage; cancel claims only
ready/held storage, then checks batch identity, restores a nonmatch, and publishes
canceled status. Repeated cancellation counts one transition. Scans are finite
and add no allocation, lock, wait, thread or global state. Tests exercise2048
competing cancel/poll cycles (half also compete with submission), unique IDs,
signals, exact terminal conservation, held timeout/capacity/reuse, wrong IDs,
stop with admitted submit, joined teardown/reset/restart and isolated instances.
Global new/delete instrumentation observes zero callback/lifecycle allocations.
Original sampled-frame transfer and Runtime tests remain unchanged.

Lifecycle scope follows existing checked stop: close admission, let admitted
callbacks finish, collect terminals and quiesce callbacks before buffer changes,
reset/shutdown/reinitialization/move/destruction. Arbitrary concurrent reset is
not claimed. Bounded cancellation can miss an exclusively held slot and return
invalid_argument; existing terminal collection/cleanup remains required.

The actual clean baseline experimental CPack, after original-prefix deletion and
relocation with custom `sdk include`/`custom data` paths, fails compiling complete
SimCore owners because `simcore/hal.hpp` forwards missing `<hal.hpp>`. Install
that existing dependency at the root inside the experimental-only block. No
supported default header/target changes. The corrected real CPack builds/runs
complete concurrent caller-thread owners, exact independent FMA-off outputs,
public loopback and modern/legacy Runtime lifecycle consumers. Compile databases
contain no checkout, private SDK build or deleted original-prefix include paths.
