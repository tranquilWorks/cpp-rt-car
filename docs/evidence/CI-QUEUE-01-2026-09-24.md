## Implementation and acceptance

Each live HazardGuard leases an independent record from the persistent registry;
release clears its protected pointer before allowing reuse. Owning guards cannot
be copied. Registry publication/scanning participates in the same sequentially
consistent order as pointer protection/removal so a newly registered guard cannot
be missed by a later reclaim scan.

Push protects its tail before dereferencing it. Pop uses the actual protected
head, independently protects its successor and revalidates the owning queue head
before reading the successor value. A successful dequeue clears the removed
head's guard before retiring it. FIFO/helping/empty behavior and incremental
reclamation remain unchanged. No global blocking lock, disabled scans or
queue-destruction-only reclamation was introduced.

Regressions verify independent nested guards and reuse, exact reclamation after
protection clears, FIFO/empty/reuse, 16 fixed-work simultaneous producer/consumer
rounds with exact-once accounting, and a paused user value copy while a competing
consumer advances and scans. Preloaded work avoids scheduler-dependent empty
polling. Existing stack/queue tests remain present.
