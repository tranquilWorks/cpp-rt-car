## Causal diagnosis and partial implementation

1. `inject_replay_boundary` searched for the first free **or** terminal slot.
   Normal admission scans all free slots first and only then reclaims a terminal
   slot. Two host-frame updates therefore occupied slots 0/1 during recording
   and slot 0 twice during replay. The canonical checkpoint includes terminal
   records and payloads. Public checkpoint comparison proved application,
   rate-dispatch and mixed-rate payloads were identical; only live-control state
   differed. Replay now follows the same bounded two-pass selection rule.
2. `begin_replay` compared aggregate historical record/payload counts to live
   mailbox capacity. A valid eight-frame history over two reusable slots failed
   before replay. It now checks the frozen retained-history capacities. Each
   injected generation still checks its own simultaneous record/payload bounds.

## Remaining blockers: history is insufficient

The public consumer has two explicit diagnostic modes, both still returning 1:

```text
--replaced: status=-16 application_state=3 callbacks=2 generations=2 accepted_before=4 accepted_after=4 invalid_before=0 invalid_after=0
--rejected: status=-16 application_state=3 callbacks=2 generations=2 accepted_before=2 accepted_after=2 invalid_before=2 invalid_after=0
```

Replaced records retain their original bytes in checkpointed mailbox slots, but
the replay journal retains only surviving generation payloads. Reconstruction
fills non-survivors with zeros; a digest cannot recover the missing bytes.
Rejected-admission actions omit mailbox/producer identity, so a multi-mailbox
recording cannot identify the counter to restore. `apply_replay_history` only
restores accepted/missed history. Guessing a mailbox, synthesizing a payload,
dropping state from the hash, or skipping final comparison would conceal the
defect. A separately reviewed artifact-format evolution is required. The concrete
proposal is [portfolio-control #463](https://github.com/tranquilWorks/portfolio-control/pull/463),
head `ac36ea8791100b25f3abab03a3bd5ba2e0240a0b`. It preserves default v1 bytes and
existing interface layouts and introduces explicitly opted-in lossless v2
admission history. It is not activated.

M23-03R acceptance items 3/4/5/10 therefore remain incomplete; M23-03, CAP-M23,
M23-04/M23-05 and subsequent milestones are not closed. This partial target
repair must remain a draft, even if its focused/default tests pass.
