## Causal correction and regressions

`Runtime::step` already captures `current` immediately before applying the
frame-owner watchdog degradation transition. The action now records that actual
prior value instead of inferring `after-1`. Unsaturated transitions retain the
same values; saturated events correctly record cap→cap. No replay comparison,
schema, layout, capacity, saturation policy, allocation or resource owner changes.

Two public regressions cover caps 1/3, disabled/below-budget/expired modes, and
ordinary active plus nested live-control v2 replay (12 configurations). Each
executes eight frames, checks callback-observed prior levels and every emitted
watchdog transition, verifies malformed input is rejected before mutation, then
checks exact final registered state, input/callback/frame/action/generation
counts and full Runtime replay success. Nested cases retain eight accepted and
eight invalid admissions. Atomic injected clocks use a 60-second logical budget;
there are no sleeps or elapsed-duration assertions.
