## Retained additional findings

The first new concurrent-owner fixture exposed process-global HighResClock
constructor writes under TSan. Constructing on a different thread instead violated
SimCore's caller-thread arena binding. Both attempts are retained. The corrected
new fixture constructs each owner on its execution thread, serializes construction,
and uses barriers before concurrent execution and destruction. Concurrent clock
initialization remains an experimental limitation outside this repair.

A required TSan run of the unchanged8-thread determinism test then exposed the
watchdog callback reading frame metadata and changing degradation state during
coordinator execution. This is a real race, not a sanitizer startup problem.
Canonical amendment591 merged at5cfbe76e5facafdcb892b7e91599e9694d532067,
blob12270b794bc7eec1b339357cba35bf03a01c0d52, after local/hosted PASS. The
callback now publishes only atomic limp/pending/trip state, with trip count last.

drains every pending trip before advancing the frame. It logs and applies the
unchanged degradation ladder at that quiescent boundary. Teardown joins the
watchdog before dependent state is destroyed. A callback-completion marker in
the diagnostic baseline copy establishes four failing assertions without using
an unsynchronized read oracle: three mid-phase setting changes and a missing
final-frame event. Repaired control passes. A fresh six-test TSan run, including
the original2/4/8-thread workload, passes. Final acceptance gates remain pending. All TSan runtime mapping failures
and genuine race reports are retained separately.

## Clock and shutdown causes found during combined validation

The first combined candidate passed48 focused tests but failed the unchanged
10-repeat matrix at repetition2, 8ThreadsFmaOff, with exit124 after180seconds.
This failed gate is retained. A debugger launched as parent of its own test
process captured frame382 sleeping21.420160ms against a1ms period, with a TSC
conversion coefficient80458805089.947205. This coefficient is calibration
state, not an actual CPU-frequency or performance measurement. The clock waited
4096reads before checking drift. A controlled public-reader outlier independently
showed an artificially future timestamp remaining in last_ns after fallback.
A separate scheduling control proves a delayed caller can overwrite a newer
monotonic floor. Both actual baseline controls fail and proposed repairs pass.

The experimental watchdog also has a lost shutdown notification: stopping and
notifying without its predicate mutex lets an idle worker begin waiting after
the notification, leaving destruction blocked. A held false predicate reproduces
this on the actual baseline source; a diagnostic exits49. Acquiring the existing
mutex to publish stop makes the controlled repaired destructor join normally.

Canonical amendment592 merged at80bb2a957bac2ed80dd63cd06a218e68b0879f74,

validation. The three production headers are SimCore.hpp, highres_clock.hpp and
rt/watchdog.hpp. The latter is experimental and is not the supported Runtime
watchdog implementation. Supported rt/src and every other rt/include file remain
unchanged. Clock samples now reject backward, nonfinite, out-of-range and greater
than1ms drift before publication; the existing calibration/default TSC selection
and threshold remain. The monotonic floor uses one compare/exchange loop.
Concurrent initialization remains unsupported by this repair. All new combined
gates below must be fresh; previous partial passes do not close acceptance.
