## Retained failures and corrections

1. The initial Runtime example used the default one-backend capacity and failed
   with `configured device backend capacity exceeded` (terminal transcript;
   initial build log `/tmp/cpp-m25-03-build.log`). Explicit capacity2 and copy-to-
   fill ordering make both native/v1 phases fit the declared one outstanding
   command. Production capacity checks are unchanged.
2. Initial ASan concurrent fixture failed its accepted/completed-count assertion
   (`/tmp/cpp-m25-03-asan.log`), with no sanitizer memory diagnostic. An instrumented
   unchanged-budget rerun passed; this alone did not erase the failure. A private
   old-poll-schedule negative control delayed the producer three seconds and
   reproduced budget exhaustion: accepted1/completed0, expected exit1
   (`/tmp/cpp-m25-03-old-poll-budget.log`). The original run did not retain these
   counters, so its exact schedule cannot be reconstructed. The fixture now yields
   to its peer on queue-full/empty polls instead of burning the finite iteration
   budget; command count, exact identities, data assertions and backend timing
   remain unchanged. Final ASan repeats and TSan passed. This is test scheduling,
   not evidence of a production repair or physical concurrency timing bound.
3. The temporary negative-control compile initially selected an unbuilt shared
   library (`cannot find -lrtfw`). Relinking the unchanged control against the
   existing sanitizer Runtime static archive produced the expected negative result.
   Both build logs are retained; no library/package wiring was changed for it.
4. Self-review found two harness cleanup hazards before publication: unconditional
   local token clearing after an unsuccessful retry, and no storage for an
   unexpected over-capacity registration token. The harness now clears only on
   success and retains a third diagnostic token slot. False-success ownership
   wrappers remain negative controls; caller storage survives unresolved cleanup.

## Risk review, rollback and limits

Self-review inspected the full scoped diff, release-ledger changes, atomic
publication/retirement, record bounds, partial-start ownership, package entry
points and defect oracles. No unresolved finding remains. Atomic counters are
nontransactional during execution; lifecycle/registry operations require joined
execution callers. Direct-copy pointers are borrowed valid host storage. Tokens
are instance-local. Real drivers must supply their own truthful ownership/fault
hooks and quiescence policy; this fixed core copy profile is not universal HAL
qualification. The kit deliberately does not assume Runtime core stop cancels
arbitrary provider-held pending work; its Runtime scenario reaches a terminal
completion before checked stop.

wiring. Preserve compiled production, public SDK headers/exports, previous
