## Acceptance and implementation

- `DeviceRateSimulationPolicy` and append-only optional binding/compiled fields
  require a positive watchdog of at most60seconds. Bind, replace and finalize
  validate copied policy and the existing deterministic-mock capability. Native
  backends cannot opt in implicitly; malformed and frozen mutation cases reject.
- Only opted-in device slots use the independent steady-clock watchdog. Logical
  admission/completion budgets and backend command timeouts remain unchanged.
  Before ordinary successful terminal/timeline/payload publication, Runtime reads
  the borrowed concurrent-safe monotonic clock and enforces the logical deadline.
  Backend timestamps stay in their declared domain. Replay uses recorded logical
  decisions; the finite host watchdog still fails a stalled replay.
- Queued/submitting/submitted/early-ready states are covered. Queued expiry never
  invokes vendor submission; accepted ownership is quarantined until checked
  cancellation/retirement/stop. Unregister failure retains ownership for retry.
  The watchdog cannot preempt arbitrary vendor code; HAL callbacks must remain
  bounded and nonblocking. Failed opted-in completions retain truthful backend
  timestamp metadata independent of the submit/completion handshake.
- Conditional graph hashing includes a versioned policy marker and watchdog.
  Default graph/config/artifact identities retain their old path. RuntimeConfig
  and artifact wire schemas, C ABIv8/SONAME8/deviceABIv1 are unchanged. Added
  compiled/private storage is covered by existing sizeof-based memory accounting.
- Independent tests cover delay, logical expiry, frozen-clock stall, all ownership
  states, native rejection, malformed/replace/frozen configuration, independent
  owners, exact memory equation, replay and cross-policy rejection. The new
  standalone allocation check exercises40 publications including active replay.
  Existing test sources, fixtures, deadlines and protected CI remain unchanged.
- Public installed consumer checks old aggregate absence, policy rejection,
  resolved inspection and real execution/cleanup. Generated source-linked SDK
  docs and release ledger are refreshed. Only current `product_sources` hashes
  in the CUDA matrix change; every retained capability/evidence row stays intact.
