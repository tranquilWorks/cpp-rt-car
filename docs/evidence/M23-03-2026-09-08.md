## Initial failures and corrections retained

- Initial strict compilation and integration attempts exposed fixture/type
  errors and a target requested before CMake regeneration. Source diagnostics
  were corrected within the benchmark scope and CMake explicitly reconfigured.
- Provider registration rejected descriptor configurations longer than the
  unchanged 64-character identifier limit. Catalog configurations were shortened;
  full timing descriptions remain in the catalog, with the identifier bound intact.
- Initial channel fixtures attempted duplicate semantic edges. Unique producer
  phases and admitted declared budgets corrected the fixture. The 256-channel
  workload uses a larger logical period; Runtime admission is unchanged.
- Initial shedding/control fixtures retained prior cursor or ordinal state.
  Explicit checkpoint resets, fresh generation handles and stream metadata fix
  those fixture errors; reset work is included in timing declarations.
- A 20 ns watchdog fixture unintentionally exercised the host monitor. The
  corrected fixture uses a 60-second logical budget with injected expiry and
  conservative admitted periods, without sleeps or an elapsed-time pass condition.
- Active loopback replay initially omitted public sampled-input registration,
  causing noncanonical completion timestamps. Public registration fixes the two
  standalone active-replay cases. Sampled I/O's existing two-slot ring limits
  replay fixtures to flight 1/2; separate device-dispatch fixtures still exercise
  the required configured flight 4. Runtime capacities are unchanged.
- The four nested replay failures remain after those fixture corrections. They
  are independently reproduced without the benchmark framework or loopback.
- The first official full run stopped in quick CTest: 30/33 passed, while three
  commands could not execute the generated `simcore_tests` (mode 0644). The
  retained binary SHA-256 was
  `86a68f7e0d522a6d8d7c1844c39db549213896dc71988d44c694372356775c4f`.
  Removing only that generated executable and relinking restored mode 0755;
  all three affected checks then passed. The cause of the earlier mode is not
  established. The original failure log remains, and the full profile was
  restarted only after this concrete build-artifact repair.
- The contract's optional-build ABI command initially found no shared library
  because only selected benchmark targets had been built. The already-built
  official full-profile library supplied the actual successful ABI/SONAME check.
- The completed strict full profile failed unchanged
  `PredictiveAdaptive.PrestepsReduceReactiveCatchup`: predictive median reactive
  catch-up 115 exceeded allowed 91 (baseline 87 + burst 4), and net median 113
  was not below baseline 87. The test uses real-time busy-spin workloads in the
  experimental SimCore path. That path and its test were not edited; the full
  profile has optional benchmarks disabled. This is a separate unresolved
  local validation failure, not a hosted utilization failure and not a passed
  gate. It was not repeatedly rerun or weakened. Its cause requires separate
  diagnosis before a full-profile pass can be claimed.
