## Defect and repair

The service thread loads a submitting slot state, then reads rate_owned for
its timeout scan. A submit error can concurrently publish terminal state to the
host, which releases the slot and clears rate_owned. Acquire on the earlier
state load does not pin that ordinary bool through host release: TSan reports
service_loop2139 reading against release_rate_batch1697 writing.

Only the private BatchSlot discriminator becomes atomic. Existing accesses now
use atomic loads/stores; state transitions, status, deadlines and publication
remain unchanged. Existing graph/cancellation flags already use atomic bool;
no new lock, allocation, thread, callback, public layout or backend change.
Storage enumeration/bounds continue using sizeof(BatchSlot), with exact
accounting gates retained. All original tests remain unchanged.

The independent CommandBatch.ActiveSubmitFailureRetiresWhileTimeoutLaneObserves
regression constructs64 actual active Runtime lifetimes (32 error and32 throwing
submissions). It requires one accepted/submitted/failed release, no cancellation,
no timeline publication, the exact completion budget and idempotent stop.
Existing successful dispatch, late completion/quarantine, timeout and stop
regressions run alongside it.
