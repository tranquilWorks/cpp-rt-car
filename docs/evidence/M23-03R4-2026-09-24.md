## Causal window and minimal correction

The existing backend submission worker scans queued slots, then loads the wake
sequence and parks if no slot was selected. A producer can publish a queued slot
and increment/notify the sequence after the empty scan but before that load.
The worker then waits on the already-new value with accepted work queued.
The correction captures the sequence before scanning. Publication is then either
seen by the scan or changes the value supplied to `atomic::wait`, preventing
this notification from being lost. Stop publication follows the same ordering.
Oldest queued selection, ownership, completion/cancel paths, waits and resources
remain unchanged.

A small private inline helper contains the production selection/park protocol.
It uses a compile-time selector over existing lane storage and allocates nothing;
no Runtime test hook, new thread, spin workaround, or timeout change is added.
The helper remains in the existing non-installed `device_manager.hpp`.

The new deterministic regression injects publication/notification after its
selector observed empty. A behavior-equivalent extraction of the original
read-after-scan order fails the progress assertion after five seconds; a second
notification rescues the negative-control worker and it joins before failure is
reported. Already-selected work and stopping controls pass. Then the observation
moves before selection; the same regression must pass. The five-second bound is
a host regression liveness guard, not a benchmark performance threshold.
