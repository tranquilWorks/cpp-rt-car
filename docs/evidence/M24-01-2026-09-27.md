## Retained failures and corrections

1. The first sample failed native registration because the injected table used
   driver v1; HAL v2 requires the v2 table. Set the full version/size and an
   explicit rejecting graph callback (no graph is registered in this batch).
   The initial declaration also incorrectly set a runtime timeout; declarations
   require zero and the provider supplies the finite per-invocation timeout.
2. An early cleanup wrapper tried to stop an unfinalized configuring Runtime
   after preparation failed. It now distinguishes no-device-ownership setup
   state from finalized/running cleanup. An injected launch/copy rejection
   then proved that public `reset_device` must settle quarantined work before
   stop. Tests retain exact reset/drain/resource counts; no backend was changed.
3. The first portable full run failed `sbom_dependencies` because the new
   worktree's GoogleTest submodule was uninitialized. Initializing the exact
   recorded submodule fixed it. The new CLI CTest initially used an out-of-scope
   Python variable and did not start; it now uses the repository's existing
   `RTFW_PYTHON_EXECUTABLE`. Original log `/tmp/cpp-m24-full-portable.log` remains.
4. TSan initially could not start due to unexpected address mappings. The
   process-only `setarch -R` launcher fixes startup without system settings.
   An extra fixed-size pthread test then crashed in the unchanged unoptimized
   Runtime finalization report path (retained backtrace
   `/tmp/cpp-m24-tsan-debug.log`). It was a different harness from M23's actual
   CLI process-stack regression. The final test uses M23's unchanged **512 KiB
   RLIMIT_STACK** method on the real sample entry point and passes with TSan;
   it neither increases that bound nor skips sanitizer execution. The embedded
   512 KiB Debug/TSan thread limitation remains explicitly unqualified; no
   Runtime stack guarantee or repair is claimed. All model/workload oracles
   and maximum capacities remain unchanged.
5. Optional real-host compilation caught use of a CUDA Runtime API error name
   in Driver API code. It now distinguishes the Driver API's NO_DEVICE and
   STUB_LIBRARY outcomes from actual errors. A first temporary archive helper
   used an unsupported Python extraction keyword; ordinary checksum-verified
   archive extraction completed instead. No toolkit artifact enters the repo.
